# Instrucciones para Codex — completar IssueCatcher
Usa el modelo de programación más económico disponible en el selector del cliente (mini si existe), esfuerzo bajo para tareas repetitivas, medio para seguridad y depuración. No cambies de modelo ni afirmes haberlo hecho si el cliente no lo permite. Evita regenerar el proyecto, leer archivos repetidamente o añadir dependencias innecesarias. Trabaja por fases y conserva la interfaz sencilla. Ejecuta comandos, no solo los describas. No borres datos ni publiques nada sin autorización. No muestres secretos.

1. Lee README, código y el documento oficial incluido en docs. Comprueba Node LTS, npm, PostgreSQL local y Docker. En Windows instala PostgreSQL mediante instalador oficial o Docker si está disponible y autorizado; detecta instalaciones existentes. Ejecuta npm install, guarda lockfile y después usa npm ci. Resuelve incompatibilidades y vulnerabilidades altas/críticas sin actualizaciones destructivas.
2. Ejecuta setup, genera secretos solo si no existen, prepara DB local y migraciones idempotentes. Separa rol migrador y rol runtime con mínimo privilegio, prueba RLS/privilegios y desactiva exposición a roles públicos de Supabase. Añade bootstrap administrativo por variables privadas, dos usuarios ficticios y notas de prueba. No incluyas credenciales en ZIP.
3. Completa RF01–08: registro, login/logout revocable, roles, CRUD propietario, teléfono cifrado, reset de un solo uso, admin y auditoría, GET /health. Añade cambio de rol auditado con protección del último administrador, alertas por fallos, rate limit por cuenta e IP persistente, mitigación de enumeración por tiempo, revocación de todos los tokens de recuperación al cambiar contraseña, redacción de logs y del inspector HTTP (no mostrar tokens ni datos personales en resultados exportables). Decide si incorporar refresh rotativo; no es obligatorio si sesión corta funciona. Asegura CSRF, cookies, CORS restringido y cabeceras. Revisa todos los casos de error y límites.
4. Completa frontend con dashboard, rutas y formularios accesibles, laboratorio de criptografía real con llave efímera independiente, historial de evidencias y pruebas protegidas predefinidas. Nunca aceptes destinos arbitrarios ni habilites endpoints vulnerables en producción. Simulaciones ficticias claramente etiquetadas. El inspector debe distinguir respuesta real, evidencia de CI, simulación y pendiente; no inventar resultados.
5. Pruebas de integración con DB aislada y Supertest para todos los RF y las diez categorías OWASP 2025; incluye concurrencia de límite de notas, IDOR leer/editar/borrar, roles, sesiones expiradas y revocadas, reset reutilizado, SQL parametrizado, XSS, cabeceras, errores genéricos y 429. Pruebas de navegador para flujos principales. Ejecuta build y audit. Añade GitHub Actions con PostgreSQL de prueba, npm ci, test y build, Dependabot, Docker no root y gitleaks. Registra resultados reales en docs/VERIFICATION.md.
6. Supabase: usa proyecto autorizado existente o solicita al usuario crear/conectar uno; no elijas proyectos arbitrarios. Configura conexión PostgreSQL TLS con CA verificada, pooler compatible si necesario, migraciones con rol separado, runtime de mínimo privilegio, sin exponer credenciales al frontend. Usa Supabase solo como BD; conserva autenticación Express. Despliega Express + frontend compilado en un host Node compatible, con HTTPS, proxy confiable configurado según topología, secretos privados, reinicio automático y SMTP real. No des por hecho que Supabase aloja Express. Si faltan credenciales, deja checklist exacto y no inventes URL.
7. Documentación: modelo STRIDE/DFD, DER, matriz OWASP con evidencia por categoría, criptografía y rotación de llaves, colección Postman, manual Windows/local/producción, demo 10 minutos. Deep Research de 2–4 páginas, 10 preguntas, tres plataformas con planes vigentes verificados, al menos seis fuentes originales. Después del despliegue autorizado ejecuta ZAP baseline, Security Headers (objetivo A), SSL Labs y pruebas controladas propias. No inventes informes ni capturas.
8. Aceptación: npm ci, test y build exitosos, DB y app levantadas, RF01–08 verificados, documentación y evidencia real o pendientes explícitos. Genera IssueCatcher-v1.0.zip sin .env, node_modules, credenciales ni datos privados. Incluye lockfile y reporte final con bloqueos. Prioriza funcionalidad y seguridad sobre estética.
